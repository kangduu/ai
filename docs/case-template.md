# 案例模板

每个案例必须能当一份 API 文档来读：看见喂进去什么、得到什么。复制本模板到主题目录，文件名建议为 `case.md`。

不要先写概念再找例子。知识点从下面四块里抽。

---

# 案例：\<一句话问题\>

- 层：\<模型基础 / 交互与控制 / 知识与检索 / 行动与编排 / 工程化落地 / 进阶选修\>
- 主题：\<Prompt / Skill / RAG / …\>
- 状态：完整 | 部分（缺输入或输出时不要标完整）

## 场景

前端工作里会碰到的具体问题。写清：谁、在做什么、卡在哪、成功长什么样。

## 输入

原文保留，不要改写成摘要。按实际出现过的内容选用，没有的块删除，不要编造。

### 用户原话

```text
（粘贴）
```

### 上下文

```text
相关文件、约束、系统提示、工具定义、git status / diff、文档切片等。
```

### 运行条件

模型、参数、是否启用某个 Skill / 工具。未知就写「未记录」，不要猜。

## 输出

一次真实或可复现的结果。好结果和失败结果都可以；失败要写清失败在哪、后来改了输入的哪一部分。

```text
（粘贴模型回复 / 轨迹 / JSON / 命令 等）
```

若有对照（改 prompt 前后、不同 temperature），分成「输出 A / 输出 B」，不要只写结论。

## 产物

可再次使用的东西，与「这一次的输出样例」分开。例如 `SKILL.md`、Prompt 模板、Agent 配置。没有产物就写「无」，不要把单次回复当成产物。

- 文件：`./SKILL.md`

## 抽出的知识点

从这次 I/O 里能带走的判断，三条以内。例如：约束写在输入侧、格式写在输出侧。
