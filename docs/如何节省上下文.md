## 如何节省上下文？

### 1. 不要每次都让 AI 重新理解项目

错误做法：

```
请先阅读整个项目，理解项目架构，
然后帮我实现一个用户管理页面。
```

问题：

- 阅读大量无关代码。
- 消耗大量 Token。
- AI 可能把注意力放在不重要的模块。
- 每次任务重复读取相同信息。

推荐做法：

建立项目知识库。

```
project/
├── AGENTS.md
├── README.md
├── docs/
│   ├── architecture.md
│   ├── coding-standards.md
│   ├── business-rules.md
│   └── module-index.md
├── src/
│   ├── components/
│   ├── hooks/
│   ├── services/
│   ├── pages/
│   └── utils/
└── ...
```

每个文件负责不同内容：

| 文件                | 主要作用              |
| ------------------- | --------------------- |
| AGENTS.md           | AI 开发规则和项目入口 |
| architecture.md     | 项目架构              |
| coding-standards.md | 编码规范              |
| business-rules.md   | 业务规则              |
| module-index.md     | 模块位置和代码入口    |

这样 AI 只需要先读取项目索引，再根据任务读取相关文件。

### 2. 使用渐进式上下文加载

这是我最推荐的方式。

不要一次性给 AI 所有资料，而是分三层加载：

L1 · 全局上下文

始终提供

技术栈、项目结构、编码规范、重要约束。

L2 · 模块上下文

按任务加载

当前业务模块、相关组件、API、Hooks、状态管理。

L3 · 细节上下文

按需加载

具体代码、错误日志、测试用例、历史实现。

例如，你要开发一个 React 用户管理页面：

L1：

```
使用 React + TypeScript。
项目使用函数组件和 Hooks。
遵循项目现有 ESLint 规则。
```

L2：

```
请读取：
src/pages/users/
src/services/user.ts
src/hooks/useUsers.ts
src/types/user.ts
```

L3：

```
请重点分析：
useUsers.ts 中的数据请求逻辑。
user.ts 中的接口定义。
现有分页组件的调用方式。
```

这样可以避免无意义的上下文加载。

### 3. 不要把所有历史对话都保留在一个会话

建议采用：

| 场景           | 会话策略 |
| -------------- | -------- |
| 一个独立 Bug   | 一个会话 |
| 一个独立功能   | 一个会话 |
| 架构设计       | 独立会话 |
| 代码重构       | 独立会话 |
| 技术学习       | 独立会话 |
| 不相关的新需求 | 新会话   |

特别注意：

新会话不等于失去项目知识。

如果项目知识已经保存在 AGENTS.md 和 docs 中，新会话只需要重新加载必要的项目资料。

### 4. 使用摘要代替冗长历史

当一个任务持续很多轮时，可以让 AI 输出交接摘要。

例如：

```
请整理当前任务的开发状态，生成交接文档。

要求：
1. 已完成的功能
2. 当前项目结构
3. 已确定的技术方案
4. 关键技术决策及原因
5. 已修改的文件
6. 当前存在的问题
7. 尚未完成的任务
8. 下一步开发计划

要求：
只保留对后续开发有价值的信息。
删除已经解决的问题和无关讨论。
输出 Markdown。
```

保存为：

```
docs/handoffs/user-management.md
```

后续开启新会话时，只需要引用这份文档。

### 5. 避免无效输出

可以在项目规则中增加：

```
AI 输出规范：

1. 优先给出结论。
2. 不要重复用户已经提供的信息。
3. 不要输出与任务无关的代码。
4. 修改代码时只修改必要文件。
5. 不要无故重复完整项目结构。
6. 解释代码时重点说明设计原因。
7. 任务完成后简要总结修改内容。
8. 如果信息不足，先说明缺失信息，不要猜测。
```

### 6. 控制 AI 的文件读取范围

这是一个容易忽略但非常重要的细节。

不要这样要求：

```
请分析 src 目录下的所有文件。
```

而应该：

```
当前任务是开发用户列表分页功能。

请先：
1. 查看 src/pages/users 的目录结构。
2. 查找项目现有分页组件。
3. 查找已有的数据请求 Hook。
4. 查找相关 TypeScript 类型。

不要读取无关模块。
如果发现依赖其他模块，再按需扩展阅读范围。
```

一个实用原则：先定位，再阅读；先阅读，再修改。
