# 目录与贡献约定

新内容必须带 **输入原文** 和 **输出样例**。只交概念文不接收。

## 案例必填

按 [case-template.md](case-template.md) 写，四块都要有着落：

| 块 | 要求 |
| --- | --- |
| 场景 | 具体问题，能判断什么叫成功 |
| 输入 | 原文；用户原话、prompt、diff、工具定义、约束 |
| 输出 | 一次真实或可复现的结果；允许失败，允许对照 |
| 产物 | 可再次使用的文件；没有就写「无」 |

另外：

- 运行条件未知写「未记录」，不要猜模型名或参数。
- 未跑过的主题不要填输出。可在 [roadmap.md](roadmap.md) 登记待补案例名。
- 输出样例 ≠ 产物。例如三条 commit 是输出，`SKILL.md` 是产物。
- 中文优先。代码、命令、`type`/`scope` 等标识符保持英文。

## 目录

有真实案例再创建主题目录，**不建空文件夹**。

| 目录 | 层 | 放什么 |
| --- | --- | --- |
| `docs/` | — | 本目录：索引、模板、地图、路径、对照、约定、路线图 |
| `llm/` | 模型基础 | 参数对比、模型对比、多模态案例 |
| `prompt/` | 交互与控制 | Prompt 原文与回复、结构化输出、tool call |
| `rag/` | 知识与检索 | 切片、命中、带引用回答 |
| `agent/` | 行动与编排 | 目标、工具列表、轨迹 |
| `skill/` | 行动与编排 | 触发语、输出样例、`SKILL.md` |
| `mcp/` | 行动与编排 | 工具/资源调用的输入输出 |
| `eval/` | 工程化落地 | 案例集、分数、失败样本 |
| `engineering/` | 工程化落地 | 流式、成本、可观测性、安全、前端接入 |

进阶层有案例再定目录，不必提前占位。

单个案例建议：

```text
<theme>/<case-name>/
  case.md       场景 / 输入 / 输出 / 知识点
  SKILL.md      若产物是 Skill
```

若主题下只有一个案例，也允许扁平成 `<theme>/case.md` + `<theme>/SKILL.md`。

## 现有 `git/` 目录

[git/SKILL.md](../git/SKILL.md) 与 [git/case.md](../git/case.md) 暂留在 `git/`，作为第一个 Skill 案例。后续可迁到 `skill/git-commit-message/`。迁移前不要为了「目录好看」先建空的 `skill/`。

## 改完案例要同步

- 在 [knowledge-map.md](knowledge-map.md) 把对应行的「待补」换成案例链接。
- 在 [../README.md](../README.md) 的「当前案例」表补一行。
- 从 [roadmap.md](roadmap.md) 勾掉已完成的待补项。

## 不要做的事

- 不改 [LICENSE](../LICENSE) 的许可条款来「配合文档」。
- 不为了凑结构去改已有产物的行为（例如重写 [git/SKILL.md](../git/SKILL.md) 的规则）。案例只描述 I/O，产物规则以产物文件为准。
