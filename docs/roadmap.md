# 路线图

按层列出**待补的真实案例**，不是待写教程。一条案例只有在具备输入原文和输出样例之后才算完成。未跑过的不要预填输出。

优先级：先补交互层与行动层（和现有 Skill 最近），再 RAG / Eval / 工程化，进阶层最后。

## 已完成

- [x] Git 提交信息（Skill）：[git/case.md](../git/case.md)

## 1. 模型基础（`llm/`）

- [ ] 同一句产品文案，`temperature` 0 vs 0.8，贴两次回复
- [ ] 同一长 Prompt，展示截断前后模型实际「看见」的差异
- [ ] 同一任务打闭源 API 与本地模型，记录质量、延迟、费用

## 2. 交互与控制（`prompt/`）

- [ ] 一次失败 Prompt 的改写前后（原文 + 两次回复）
- [ ] JSON Schema 抽取：用户口语 → 合法 JSON，附一次解析失败
- [ ] Function Calling：工具定义 + 用户话 → 实际 tool call 参数

## 3. 知识与检索（`rag/`）

- [ ] 对一份自己的文档提问：切片、命中片段、带引用回答
- [ ] 两种 chunk 大小对同一问题的命中对比
- [ ] 同一问题分别只用 Prompt 和加上 RAG，对比是否还在编造

## 4. 行动与编排（`agent/` `skill/` `mcp/`）

- [x] Skill：根据 diff 写 commit（见上）
- [ ] 一次带工具的 Agent：目标、工具列表、完整轨迹、最终结果
- [ ] 一次 MCP 调用：资源或工具描述 + 实际返回
- [ ] 同一任务用确定性工作流 vs 自主 Agent，对比步数和失败点
- [ ] （可选）将 `git/` 迁入 `skill/git-commit-message/`，不改 Skill 行为

## 5. 工程化落地（`eval/` `engineering/`）

- [ ] Eval：用已有 Git 案例扩成小集合，打分并留下失败样本
- [ ] 前端流式接入：一次 SSE（或等价）请求的网络日志 + 取消
- [ ] 护栏：一条含密钥或注入的输入，以及拦截后的输出
- [ ] 一次失败请求的 trace：prompt 版本、工具调用、归因

## 6. 进阶选修

- [ ] 一组 Prompt/RAG 仍失败的样本，写「现在值不值得微调」
- [ ] 同一编排需求的一次真实框架尝试（自研或现成库）+ 放弃/采用理由

## 文档本身

骨架已就绪。之后只随新案例改地图、README 案例表和本页勾选，不为空主题写概念章。
